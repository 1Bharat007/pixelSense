# Empty State System

## Philosophy
An empty screen is a failure of communication. Empty states must be intentionally designed to reassure the user and guide their next action.

## Core Rules for Empty States
Every empty state must answer four questions:
1. **Why is this empty?** (e.g., "No history yet.")
2. **Is something wrong?** (e.g., "This is normal for a fresh installation.")
3. **What can I do?** (e.g., "Wait for the sun to set, or adjust brightness manually.")
4. **Should I wait?** (e.g., "We will generate insights after 24 hours of use.")

## Visual Implementation
- No blank pages.
- Empty states must use subtle, monoline illustrations that match the PixelSense Brand System (Luminance). 
- Primary CTA buttons should be present if a user action can populate the state (e.g., "Connect Sensor").
